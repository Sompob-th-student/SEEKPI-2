ฉบับนี้ใช้แทนฉบับก่อนหน้า ทีมศึกษาหน้าจอจริงของ SEE KPI เดิมแล้วพบว่า ระบบเดิมให้คะแนน KPI จาก ค่าเป้าหมาย 5 ระดับในแต่ละงวด ใช้เกรด FE‹S› / EE‹A› / FM‹B› / PM‹C› / NM‹D› และตั้ง น้ำหนัก Structure แยกตาม Level Group ตอนนี้ SEEKPI-2 ทำงานแบบเดียวกันแล้ว แต่บางกติการะบบเดิมคำนวณที่ Server ซึ่งตรวจสอบจากภายนอกไม่ได้ จึงต้องให้ HR ยืนยัน

ตัวอย่างตัวเลขทุกข้อคำนวณจากโค้ดจริงของระบบ ค่าที่ ทำเครื่องหมาย ☑ คือค่าที่ระบบใช้อยู่ตอนนี้ หาก HR เห็นด้วยทั้งหมด ตอบกลับว่า "ยืนยันตามที่เสนอ" ได้เลย

สรุป 11 ประเด็น

#ประเด็นค่าที่ระบบใช้ตอนนี้ผลกระทบHR ยืนยัน / แก้ไข
1ผลแย่กว่าเป้าระดับ 1 ได้กี่คะแนน0กลาง: KPI ที่พลาดหนักบางงวด☐ ยืนยัน ☐ แก้ไข
2คะแนน KPI จากหลายงวดค่าเฉลี่ยของทุกงวดที่มีผลสูง: เปลี่ยนคะแนนของ KPI ทุกข้อที่เป็น Monthly / Quarterly☐ ยืนยัน ☐ แก้ไข
3คะแนนระหว่างระดับขั้นบันได (ได้ระดับที่ถึง)กลาง: ความละเอียดของคะแนน☐ ยืนยัน ☐ แก้ไข

6เศษเท่ากันตอนปัดจำนวนคนต่อเกรดให้เกรดที่ใกล้ FM ก่อนกลาง: เปลี่ยนจำนวนคน PM / NM ได้ 1 คน☐ ยืนยัน ☐ แก้ไข
7ขนาดกลุ่มขั้นต่ำของ Force Rank5 คนกลาง: หน่วยงานเล็กไม่ถูกบังคับ Bell curve☐ ยืนยัน ☐ แก้ไข

11วิธีรวมผลของ SUM UPผลรวมสำหรับ KPI ที่ตั้ง Sum Up นอกนั้นเฉลี่ยกลาง: คะแนนของหัวหน้างานและ Scorecard องค์กร☐ ยืนยัน ☐ แก้ไข
1

ผลแย่กว่าเป้าระดับ 1 ได้กี่คะแนน

แต่ละงวดได้คะแนนเท่ากับระดับสูงสุด (1–5) ที่ผลจริงทำได้ ถ้าผลจริงแย่กว่าระดับ 1 ต้องตัดสินว่าจะได้ 0 หรือ 1

  • 0 คะแนน ค่าที่ใช้ตอนนี้
  • 1 คะแนน (ต่ำสุดเท่ากับระดับ 1)
ตัวอย่าง: LTIFR (Quarterly) เป้า L1–L5 = 1.0 / 0.8 / 0.6 / 0.4 / 0.2 ผลจริง 0.5 / 0.3 / 1.2 ได้คะแนนงวด 3 / 4 / ? ค่าที่ใช้ตอนนี้: คะแนน KPI = (3 + 4 + 0) ÷ 3 = 2.33 · ทางเลือกที่ 2: (3 + 4 + 1) ÷ 3 = 2.67
2

คะแนน KPI จากหลายงวด

KPI แบบ Monthly มี 12 งวด และแบบ Quarterly มี 4 งวด ต้องตัดสินว่าคะแนน KPI ทั้งปีมาจากอะไร

  • ค่าเฉลี่ยคะแนนของทุกงวดที่มีผล ค่าที่ใช้ตอนนี้
  • ใช้คะแนนของงวดล่าสุด
  • รวมผลจริงทุกงวดก่อน (เฉลี่ย / รวม / ล่าสุด ตามประเภท KPI) แล้วจึงเทียบกับเป้าทั้งปี
ตัวอย่าง: SPI (Monthly) เป้า 0.85 / 0.90 / 0.95 / 1.00 / 1.05 ผลจริง Jan–Oct = 0.97, 1.01, 0.94, 0.99, 1.02, 1.06, 0.92, 0.98, 1.00, 1.03 เฉลี่ยคะแนนรายงวด: 3.40 · ใช้งวดล่าสุด (Oct = 1.03): 4 · เฉลี่ยผลจริงได้ 0.992 แล้วเทียบเป้า: 3

ฟอร์ม KPI ของระบบเดิมมีตัวเลือก Sum Up และ Prorate ซึ่งอาจหมายถึงทางเลือกที่ 3 ควรยืนยันกับผู้ดูแลระบบเดิม

3

คะแนนระหว่างระดับ

ถ้าผลจริงอยู่ระหว่างสองระดับ จะให้คะแนนเป็นจำนวนเต็มของระดับที่ทำได้ หรือคิดตามสัดส่วนระหว่างระดับ

  • ขั้นบันได (ได้ระดับที่ถึง) ค่าที่ใช้ตอนนี้
  • คิดตามสัดส่วนระหว่างระดับ (Interpolation)
ตัวอย่าง: SPI งวด Jan ผลจริง 0.97 อยู่ระหว่าง L3 (0.95) กับ L4 (1.00) ขั้นบันได: 3 · Interpolation: 3 + (0.97 − 0.95) ÷ (1.00 − 0.95) = 3.40
4

ช่วงคะแนนของเกรด FE–NM

ถ้าทุก KPI ได้ตามเป้าพอดี (ระดับ 3) คะแนนรวมคือ 3 ÷ 5 × 100 = 60.00 ช่วงคะแนนของเกรดจึงต้องสอดคล้องกับจุดนี้

  • FE ≥ 90 · EE ≥ 75 · FM ≥ 55 · PM ≥ 40 · NM ต่ำกว่า 40 ค่าที่ใช้ตอนนี้
  • ใช้ช่วงคะแนนจาก Grade Criteria จริงในระบบเดิม (กรุณาแนบมา)
ตัวอย่าง: พนักงานคะแนนรวม 65.11 (3.26) ได้ FM‹B› ตามค่าที่ใช้ตอนนี้ ถ้าระบบเดิมเริ่ม FM ที่ 65 คนนี้ยังได้ FM แต่คนที่ได้ตามเป้าพอดี (60.00) จะตกไปเป็น PM

ข้อนี้กระทบเกรดและเงินของพนักงานทุกคน ควรได้ค่าจริงก่อนเริ่มพัฒนา

5

น้ำหนัก Structure ของแต่ละ Level Group

ระบบเดิมตั้งน้ำหนัก Company / Project / Individual Performance / Competency แยกตาม Level Group (พบ 20 กลุ่ม เช่น Site OP1, HQ Mgr., Director Group) ตอนนี้ SEEKPI-2 ใช้ค่าตัวอย่างเพียง 4 กลุ่ม

  • ค่าตัวอย่าง: Management 20 / 50 / 0 / 30, Engineer 0 / 40 / 40 / 20, Supervisor 0 / 50 / 50 / 0 ค่าที่ใช้ตอนนี้
  • นำเข้าตาราง Appraisal Criteria จริงทั้ง 20 Level Group จากระบบเดิม
ตัวอย่างจากระบบเดิม: ระดับบริษัท 100 / 0 / 0 / 0, ระดับฝ่ายงาน 0 / 100 / 0 / 0 และพนักงานหน้างานคนหนึ่งได้ Project 50% / Individual 50%
6

เศษเท่ากันตอนปัดจำนวนคนต่อเกรด (Force Rank)

จำนวนคนต่อเกรดคิดจากสัดส่วน FE 10% · EE 20% · FM 50% · PM 15% · NM 5% ด้วยวิธี Largest Remainder ถ้าเศษของสองเกรดเท่ากัน ต้องตัดสินว่าจะให้ที่นั่งกับเกรดไหน

  • ให้เกรดที่ใกล้ FM ก่อน (ถ้าห่างจาก FM เท่ากันให้เกรดที่ต่ำกว่า) ค่าที่ใช้ตอนนี้
  • ให้เกรดที่ต่ำกว่าก่อนเสมอ
  • ให้เกรดที่สูงกว่าก่อนเสมอ
ตัวอย่าง: หน่วยงาน 10 คน โควตา PM 1.5 และ NM 0.5 (เศษเท่ากัน) เหลือ 1 ที่นั่ง ค่าที่ใช้ตอนนี้: PM 2 · NM 0 · ทางเลือก "เกรดต่ำกว่าก่อน": PM 1 · NM 1
7

ขนาดกลุ่มขั้นต่ำของ Force Rank

ถ้าบังคับสัดส่วนเกรดกับกลุ่มเล็ก ผลจะบิดเบือน

  • กลุ่มที่มีน้อยกว่า 5 คนไม่บังคับ ใช้เกรดจากคะแนน ค่าที่ใช้ตอนนี้
  • เพิ่มขั้นต่ำเป็น 10 คน
  • รวมกลุ่มเล็กเข้ากับหน่วยงานแม่ก่อน
ตัวอย่าง: ทีม 4 คน คะแนน 88.4 / 84.0 / 79.2 / 75.6 ได้ EE ทั้ง 4 คนตามคะแนน Vertical Force Rank ของระบบเดิมจัดกลุ่มตาม Force Rank Group ของหน่วยงาน ข้อนี้จึงตัดสินว่าหน่วยงานเล็กจะถูก Calibrate หรือไม่
8

Force Rank ปรับเกรดขึ้นได้หรือไม่

Force Rank จัดเกรดตามอันดับในกลุ่ม คนที่อันดับต้นจึงอาจได้เกรดสูงกว่าเกรดจากคะแนน

  • ปรับได้ทั้งขึ้นและลง ค่าที่ใช้ตอนนี้
  • ปรับลงได้อย่างเดียว (ไม่ให้สูงกว่าเกรดจากคะแนน)
ตัวอย่าง: หน่วยงาน 7 คน E101 ได้คะแนน 88.40 (เกรดจากคะแนน EE) และเป็นอันดับ 1 จึงได้ที่นั่ง FE ค่าที่ใช้ตอนนี้: FE (ขึ้นเงินเดือน 8%, โบนัส 3 เดือน) · ทางเลือกที่ 2: EE (6%, 2 เดือน)

ตัวเลข % ขึ้นเงินเดือนและโบนัสเป็นค่าตัวอย่าง ขอให้ C&B แนบตาราง Grade Criteria จริง

9

Value Get Zero (ถ้าเปิดใช้ Structure หักคะแนน)

Config ปัจจุบันของระบบเดิมไม่ได้ใช้ Structure หักคะแนน แต่ระบบรองรับไว้ หากจะใช้ในอนาคตต้องตัดสินความหมายของ Value Get Zero

  • คะแนนรวมทั้งหมดเป็น 0 ค่าที่ใช้ตอนนี้
  • เฉพาะ Structure ที่หักคะแนนเป็น 0
ตัวอย่าง: คะแนนรวม 65.11 แต่ขาดงาน 3 วัน (Value Get Zero = 3) คะแนนรวมจะเป็น 0 ตามค่าที่ใช้ตอนนี้
10

KPI ที่ถูก Waive (ยกเว้น)

ระบบเดิมมีสวิตช์ Waive ต่อ KPI ในหน้าประเมิน ใช้เมื่อ KPI วัดไม่ได้ เช่น โครงการถูกยกเลิก ผู้ประเมินต้องระบุเหตุผลทุกครั้ง

  • ไม่นับ KPI นั้น และปรับน้ำหนักของ KPI ที่เหลือรวมเป็น 100% ค่าที่ใช้ตอนนี้
  • นับเป็น 0 คะแนน
  • ให้คะแนนกลาง (ระดับ 3) แทน
ตัวอย่าง: Individual Performance มี 3 KPI ได้ Weight Score 18.00 (30%), 24.00 (40%) และ 21.00 (30%) แล้ว Waive ข้อสุดท้าย ค่าที่ใช้ตอนนี้: (18 + 24) × 100 ÷ 70 = 60.00 · นับเป็น 0: 42.00 · ให้คะแนนกลาง: 18 + 24 + 18 = 60.00
11

วิธีรวมผลของ SUM UP

ปุ่ม SUM UP ดึงผลจริงของ KPI เดียวกันจากลูกทีมมาเป็นผลของหัวหน้า (หรือของ Scorecard องค์กร) ทีละงวด

  • ผลรวมสำหรับ KPI ที่ตั้ง Sum Up (จำนวนครั้ง / ยอดเงิน) นอกนั้นใช้ค่าเฉลี่ย ค่าที่ใช้ตอนนี้
  • ถ่วงน้ำหนักตามขนาดงานของลูกทีม (เช่น มูลค่าโครงการ)
ตัวอย่าง: SPI งวด Jan ของลูกทีม 3 คน = 0.97, 1.03, 0.94 ได้ค่าเฉลี่ย 0.98 จำนวนรายการปรับปรุง Audit (ตั้ง Sum Up) = 2, 1, 0 ได้ผลรวม 3

วิธีตอบกลับ

ตอบกลับทางอีเมลโดยระบุเลขข้อและทางเลือก เช่น "ข้อ 2 เลือกทางเลือกที่ 3, ข้อ 4 ใช้ช่วงจากระบบเดิม" ข้อที่ไม่ระบุจะถือว่ายืนยันตามค่าที่ใช้ตอนนี้

ขอให้แนบข้อมูลจริงจากระบบเดิมมาด้วย ได้แก่ ตาราง Appraisal Criteria (น้ำหนักตาม Level Group), Grade Criteria (ช่วงคะแนน, % ขึ้นเงินเดือน, เดือนโบนัส, Percent Budget) และ Force Rank Group เพื่อให้ทีมเทียบผลกับระบบเดิม 1 รอบก่อนใช้งานจริง
